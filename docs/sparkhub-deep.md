## 二、字符串解码器（已完全还原）

主循环片段：
```lua
while e <= x do
  local K = I(q, e, e)          -- 读一个字符
  local P = t[K]                -- 字符 → 0..63
  if P then
    G = G + P * (64 ^ (3 - w))
    w = w + 1
    if w == 4 then
      w = 0
      C(X, k(floor(G/65536), floor((G%65536)/256), G%256))   -- 4 字符 → 3 字节
      G = 0
    end
  elseif K == "=" then
    C(X, k(floor(G/65536)))     -- 尾巴
  end
end
```

常量：`base=64`、`每 4 字符一个 24 位数`、除数 `65536 / 256 / 1`。

**注意**：K 元素里含有 t 表之外的字符（`?` `<` `(` 等），说明 K 元素**不是**纯 base64；
它们作为「混淆标识符」直接当表键用，不需要解成可读文本。

## 五、踩过的坑（务必记住）

1. **TAILCALL 不触发 `call` 钩子** —— 用 `debug.sethook` 抓不到 VM 主函数，
   因为外层是 `TAILCALL 2 8 1k`。必须用 `"return"` 事件或 patch 源码。
2. **脚本是 stripped 的** —— `luac -l -l` 只有寄存器号，没有变量名。
3. **`__index` / `__gc` / `__len` 是运行时拼接的** —— 搜字符串搜不到。
4. **万能 proxy 会导致死循环** —— `__len` 返回 0 让循环永不退出，必须加步数上限。
5. **G 和 W 通过 upvalue 互相引用（自举）** —— 单看任何一个函数都不完整。

## 八、动态分析的实验记录（2026-10-25 中午）

### 尝试过的 harness

在 `lua` 5.4 里 stub Roblox 环境跑 `loader.lua`，依次修好了：

| 问题 | 修法 |
|---|---|
| `getfenv` 不存在 | stub 成 `return _G` |
| **`newproxy(true)` 返回 `{}` 无元表** | **必须 `setmetatable(t, {})`** ← 关键 |
| `unpack` 在 5.4 是 `table.unpack` | stub |
| 各种 Roblox API | proxy / 空表 |

修完 `newproxy` 后 VM **真的跑起来了**（`G` 被反复调用），错误从
`attempt to index nil (local 'k')` 推进到 `attempt to call nil (local 'Q')`。

### 为什么放弃动态路线

层 2 的变量快照显示大量 nil：
`CV, Ck, pk, mk, s, Qk, Hk, ek, Bk ...`

这些是 VM 依赖的 Roblox API / 服务对象。**在 Lua 里补 Roblox 环境是无底洞**，
每修一个就会冒出新的。结论：动态分析不可行，必须静态逆向。

### 已验证的事实（动态）

- VM 主函数的参数 0（`m`）= **空表**（`table(0 keys)`）
- 字节码**不在参数里**，由 `W(10913423, {})` 构造过程中产生
- `G` 内部：`if t then local x = t(true) local k = D(x)`，其中
  `t = newproxy`, `D = getmetatable`（由 7 个外部参数按序传入）
