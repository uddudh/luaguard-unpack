# luaguard-unpack（中文说明）

把 [Lua-Guard](https://lua-guard.xyz) 保护过的 Lua 脚本拆成可读内容。
**不需要执行器、不需要 `crypt` 库、不需要开游戏**，只要有 Node。

```bash
node luaguard-unpack.mjs 被保护的文件.lua -o unpacked

# 也可以直接喂链接，不用先下载
node luaguard-unpack.mjs --url https://example.com/protected.lua -o unpacked
```

## 产出

| 文件 | 内容 |
|---|---|
| `segNN.b64` | 原文件里的 base64 数据段 |
| `blob.bin` | 拼接解码后的打包二进制 |
| `strings.json` / `strings.txt` | 加密字符串表，**全部解密** |
| `globals.json` | 全局数值常量 |
| `disasm.txt` | 每个函数原型的反汇编（opcode 已命名） |
| `structure.json` | 机器可读的完整结构 + 校验结论 |

## 为什么结果可信

Lua-Guard 自己带了三个完整性校验，本工具全部复算，**校验不过会明确告诉你，而不是输出垃圾**：

1. **全局 HMAC** —— 加载器签名整个 payload 并与写死的摘要比对（盐是通过「试候选值并验证 HMAC」找出来的，所以变量改名也挡不住）
2. **每个原型的算术校验和** —— 字段布局错一个字节就会失败
3. **字节精确消耗** —— 正确解析会正好用完 payload，剩字节就说明格式不同，会警告

成功时输出 `done — fully verified`，退出码 0；有警告退出码 3，可以直接用在脚本里。

## 参数

```
-o, --out <dir>   输出目录（默认 ./unpacked）
--verify          只校验，不写文件
--no-disasm       跳过反汇编（大文件更快）
--quiet           只输出错误和最终结论
```

## 两层加密，都被处理了

Lua-Guard 的「加密脚本」其实加了两层，本工具**两层都解开**，全程不需要 Roblox 和执行器：

1. **外层**：几万段短 base64 组成的表 + 一段纯 Lua 写成的解密器（手写 SHA256、base64、逐字节 XOR）。
   它**混入诱饵段**，并用一个排列数组打乱真实段的顺序：

   ```
   key       = sha256(盐 ":" scriptId ":runtime")
   plaintext = XOR( base64decode( concat( 段[order[i]] ) ), key )
   ```

   只用 `order.length` 段（例如 32112 段里只用 32097 段，其余 15 个是垃圾），
   并且 base64 文本里还撒了垃圾字符，靠 gsub 过滤掉。顺序或诱饵数量错一点，出来的就是乱码而不是报错。

2. **内层**：下面「格式要点」说的那套（base64 段 + 自研 VM 字节码）。

两层都拿原程序自带的校验值验过，所以跑通 = 逐字节正确，不是「看起来差不多」。

## 版本参数（自动识别）

Lua-Guard 每出一个新版本就把整套参数换掉，所以这里没有任何硬编码。工具会依次尝试所有已知
配置，接受第一个「每个原型的校验和都通过」且「blob 正好被读完」的。

| 参数 | v1 | v2 | v3 |
|---|---|---|---|
| LCG 种子 | 348 | 617 | 52 |
| LCG 混合 | `i*17+173` | `i*25+70` | `i*31+231` |
| 3 字节字节序 | `b1 b0 b2` | `b2 b0 b1` | `b1 b0 b2` |
| 4 字节字节序 | `b3 b1 b2 b0` | `b2 b3 b0 b1` | `b2 b0 b3 b1` |
| opcode 乘数 | 143 | 151 | 97 |
| 校验常数 | 4442017 | 736242 | 2608344 |
| 指令数组顺序 | op,c,a,b | b,a,c,op | b,op,c,a |
| 字符串表字段序 | id,t,iv,tag | 密文,iv,id,tag | iv,id,tag,密文 |

三个版本共用的部分：外层解密、AES-256-CBC 字符串解密、`3.<base64>.<hex>` 标签格式。

## 格式要点

- 三字节字段的字节序很怪：`(b1<<16 | b0<<8 | b2) - 0x800000`；四字节字段同样「第二字节进高位」，**不能当小端处理**
- 每个函数原型用自己的密钥偏移，去异或一个 32 字节 LCG 密钥流
- 操作数分三组（op / C / A / B）分别用该密钥的不同相位解密（种子 7 / 5 / 6，步进 3，32 循环）
- opcode 再做 `((op - shift) * 143) % 256` 混淆
- 字符串表是 AES-256-CBC，`key = hex2bin(sha256hex(盐..":enc:"..id))`，IV 每条单独存

反汇编里的 opcode 名字是从 VM 自己的 50 个 handler 体里读出来的，是真实语义。

## 局限

- 只做**反汇编**，不做反编译（控制流没重建、局部变量没名字）。但每个 `LOADK` / `GETGLOBAL` 后面都标了常量值，已经接近伪代码；想找某个 API（`BillboardGui`、`KillAura`）直接搜 `disasm.txt` 就行。
- 布局是版本相关的。新版 Lua-Guard 若改了字段顺序或密钥调度，工具会告诉你卡在哪一步，不会假装成功。

## 已验证

一份 2.37MB 的 Roblox 外挂脚本（解密后 1.57MB）：42 段 → 991,613 字节；185 个全局常量；**1,441 个字符串全部解密**；803 个函数原型、54,344 条指令，**全部校验通过**。
